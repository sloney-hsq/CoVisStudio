# CoVisStudio：研究完成计划

目标：完成一篇有真实证据支持的 CSCWD 论文。研究问题与两个条件保持不变；工作围绕实验可执行、结果可核验和论文可解释展开。

## 1. 固定要回答的问题

在同一全双工语音环境中，把“引用哪份证据、修改哪些当前视图、保留或解除哪些条件”显式展示并允许纠正，能否改善修订正确性和用户理解，其时间与修复代价是多少？

B0 与 B2 共用模型、分析指令、历史/保存集合工具、成员解析、实际查询、澄清规则和提交权限。B2 显示可检查、可纠正的修订支持，B0 保留普通交互和执行回执。这是一个支持方案的整体比较，不拆出卡片组件、输入模态或反馈时机的新因素。

两组都能在播放期间接收语音。全双工提供持续修订的场景，本实验不检验它相对文本或轮次语音的优越性。原生会话采用相同保留与取消政策，归档实际出站输入；不承诺模型的全部历史只包含用户已经听到的内容。不能把无法实现的“完全冻结原生历史”当作必须无限期等待的工程目标。

| 工作 | 当前证据 | 还缺什么 |

| 公平基线 | 统一两组分析指令；移除模型上下文和修订卡中的冗余条件标识；受控读写差异为零 | 自然使用轨迹与正式材料的最终审阅 |

## 3. 三条并行工作线与分工

| 工作线 | 主要负责人 | 立即交付物 | 完成标准 |
| --- | --- | --- | --- |
| 运行与测量 | 实时接口子代理实现，主代理集成 | 分段和取消修复、日志、离线回归、浏览器验证 | 无旧工具执行；输入不静默丢失；提交与播放可追溯；失败不伪报完成 |
| 材料与评估 | 研究材料子代理，主代理审阅 | 四类业务任务说明、独立意图编码包、理解题、逐任务结果表 | 不预设参与者必须选哪组；先标注意图再看结果；保留未知、失败和重复尝试 |
| 对照与论文 | 公平性子代理审计，主代理统稿；用户安排参与者和人工审核 | 同等能力审计、冻结版本、结果图表和英文稿 | 两组仅有声明的支持差异；结论与证据对应 |

同一文件只由一个执行者修改。主代理负责合并与一次相应范围的验证，避免多个代理重复改同一模块或反复运行整套测试。

## 4. 执行顺序和交付门槛

### 阶段一：收口当前修复（本工作段）

完成分段、取消和公平性修复，运行针对真实失败顺序的回归以及一个完整浏览器流程。保存当前源文件摘要、修复前记录和全部验证结果。当前已完成这些本地验证；不再同时扩展图表类型、模型数量或新的实验条件。

### 阶段二：一轮有限真实复测（下一工作段）

建议预先固定六次连接：季度修订、本地重排、历史成员迁移三个已失败场景，各跑两个运行路径一次。每次最多60秒，每段完整输入最多10秒，复用已有合成语音，无自动重试；不额外合成、不失败后临时加提示。每次记录实际连接时长、usage、输入、工具、提交、渲染、播放和终止原因。

验收检查的是：完整修订能进入当前请求、取消后能够按正确协议继续、实际结果可评估。模型做错仍作为有效观察保留；不要求靠反复调参把六次都刷成成功。若基础传输再次阻断修订，停止扩大采集并修该具体故障。下一轮尚未自动调用。

### 阶段三：冻结正式实验材料（与阶段二准备并行）

保持四个业务家族及已有平行版本：地区服务分析、当地优先级重选、季节比较、指标替换。业务目标与必要约束固定；对象选择、保留或解除由参与者表达。当前编写案例的 `expected_sources` 只用于诊断，不能作为参与者意图答案。

冻结以下五份实际材料：英文任务卡与练习、B0/B2 条件说明及输入政策、独立意图编码表、相同的理解题、首次正式尝试与未知结果处理规则。两到三人的流程试跑只检查操作和材料，不用于报告方法收益，也不据条件胜负削弱基线。

### 阶段四：正式采集与同步编码

沿用当前30人的招募目标，每人四个任务、每种条件两次；30是计划，不是已经完成的样本或功效保证。预计每人约50分钟，单实验席约25小时纯实验时间，另留预约和休息时间。现有系统是单活跃会话，排期不能假定同一实例同时接待多人。

参与者招募可以现在开始安排，正式数据在材料冻结后采集。两名编码者在采集期间同步独立编码；先锁定意图，再打开结果映射和独立 SQL 核验。原始语音核听、理解与修复判定不由脚本自动通过。

### 阶段五：统计和论文定稿

主要结果固定为修订正确性与理解，修复成本和时间为次要结果。以参与者为独立单位进行配对比较，报告差值和95%区间；两个主要检验按既定 Holm 方案校正。所有分配任务进入分析，未知单列并给出识别范围；失败者不能从耗时比较中消失。

先形成一张结果表和两到三个能由轨迹核验的过程案例，再写实际发现与限制。现有中文稿的方法与相关工作保留，在结果确定后更新实验段并翻译英文。稿件不预填显著性、不把满意度当正确性、不把 API 诊断当用户实验。

## 5. 建议排期

| 相对工作日 | 主要交付 |
| --- | --- |
| 第1天 | 当前工程收口；真实复测准备；任务、招募安排并行 |
| 第2天 | 有限复测和流程试跑；冻结材料与分析规则 |
| 第3—7天 | 按单席容量采集，人工编码同步进行 |
| 第8—9天 | 分歧处理、独立数值核验、统计与过程案例 |
| 第10天 | 英文完整稿及导师审阅版 |

这是有参与者和编码者配合时的执行目标，不是保证十天后出现正向结果。主要进度瓶颈将从代码转为招募和人工证据。自动化应减少整理工作，不能代替这些证据。

## 6. 每次汇报只回答四件事

已完成哪项交付；什么实际证据通过；仍有哪些具体故障或未审字段；下一项交付是什么。代码行数、子代理数量和检查数量不作为论文贡献指标。

实验可能发现正确性提高、理解提高、成本增加或没有清晰差异。论文结论由结果决定；本计划固定的是问题、方法和可判定的证据。
