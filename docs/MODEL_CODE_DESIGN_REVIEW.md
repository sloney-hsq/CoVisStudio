# CoVisStudio：模型、代码、界面与研究一致性审查

日期：2026-11-13。范围是当前 CoVisStudio，未修改 VerbalVis 或 DuplexVisEval。三名 GPT-6.1 Sol 子代理分别承担前端、原生实时协议、工具与研究核对；主代理整合、执行两次真实 API 并核对界面。

## 总判断

当前项目已有可以继续研究的完整分析链，但不能称为已经证明有效的 CSCWD 方法。最优先的问题是正确执行用户请求、让人看懂实际改动，以及让论文主张和实际对照一致。本轮没有新增实验因素、自动重试或付费协调模型。

## 已确认的实现问题

| 问题 | 实际后果 | 本轮处理与证据 |
| --- | --- | --- |
| 工具异步执行期间新输入越过未完成的原生工具回执 | 新 response 创建时旧 function call 仍悬空；旧任务结束直接返回，原生轮次未闭合 | providers.py 复用 draining 门禁。旧执行不再发布数据，只回传明确 superseded 回执并确认后继续。4 个受控回归；原生特定迟到序列本轮未再次触发 |
| 固定品类筛选错误标记成固定月份／地区成员 | 数值正确，模型收到的集合含义却不正确 | data.py 只对 category 分组标 fixed，其他维度保留真实 categories 筛选并标 observed/all；独立 Olist SQL 回归 |
| 删除放大查看的图表后 overlay 仍引用旧对象 | 两个 Vue TypeError，已删除图仍停在屏幕 | App.vue 在公开状态不再包含该图时关闭 overlay；原始失败截图及修复后浏览器检查保留 |
| 保存集合的 HTTP body 可覆盖 URL 指定集合 | 实际应用的集合可以与选中的接口对象不同 | app.py 以 URL 集合 ID 为准；测试两套不同真实成员，验证目标集合及当前条件 |
| 提交后的模型续接可能重新上传旧截图 | 新 03 中 r7 已渲染，仍上传 r6；r7 截图稍后才到 | 已修复：工具异步任务在事务锁外等到同版本真实截图／显式空画布，再回传原生回执；首次创建、删除最后一图、等待时插话均覆盖 |

更正旧测试不是删除正确性约束：原 `test_model_flow` 只允许一个工具回执；现明确检查一个不含旧数据的 superseded 回执、一个正确的 Q1 提交回执，仍要求旧半年结果从未发布。

## 模型层面：哪些改了代码仍没有解决

两次真实调用使用 `qwen3.8-omni-flash-realtime`，完整原始自然合成输入为 4.24 秒、8.08 秒或 6.64 秒，无新 TTS、无自动重试。真实调用结束后连接均已关闭。

| 案例 | 实际结果 | 解释 |
| --- | --- | --- |
| 02：讲解时解除固定集合，三图重新选当前地区订单前三 | 失败，连接墙钟 19.89 秒，无新提交 | 工具参数原文为 `top_n:"3"`。出站 schema 及服务端确认均要求 integer/null，数字提示也已送达。不是客户端漏发 schema，不能靠再写一句提示宣称解决 |
| 03：讲解时沿用历史 Q1 品类，只修改当前 Q3 的两张服务图 | 成功，连接墙钟 33.75 秒，一次 r6→r7 提交 | 正确保留 RJ、Q3、各自指标和图一。最终 355200/355200 音频采样自然交付。历史证据已显式选择，不能声称模型仅凭播放位置推断引用 |

两次真实晚到的前半段 ASR 都进入最终接受的话语，说明片段关联修复在这两个顺序中有效。02 仍把 “Release fixed categories” 转成 “These fixed categories”；保留片段不等于识别准确。两次未出现原生迟到 response.created 工具竞态，故不能宣称该特定竞态已真实重现并解决。

独立 SQL 检查六张最终图的实际查询全部相符，但 02 的实际查询不是用户要求的新排名。人工核听、语音意义一致性与用户理解仍待审。

## 前端设计判断与实际改动

保留三个图表为视觉中心：业务规模、低评分率和配送天数用相同品类行次对照；稳定图号和选中状态决定修订目标；每图保留地区、时间、订单状态和成员选择依据。研究控制不与参与者的分析工作混放。

本轮提高标题、范围、成员与底注层级和对比度，消除原生 4K 下 Journey 前的过度空白。1920、2560、3840 CSS 宽度均检查三图、溢出与页面错误。参与者视图隐藏实验分配和任务配置入口，研究者本地入口保留。

修订卡用实际数据说明“来源／作用于哪里／改变什么／保留什么”。保留条件显示具体 Measure、Period、Order status、Comparison set、Ranking 值，不能仅列代码字段名。普通当前范围修改与历史证据复用采用不同标题，避免诱导用户误以为必须回到历史。

这些是可用性与表达改进，截图美观不能替代用户理解证据。页面没有增加一排研究评分或内部日志面板。

## 后端设计判断

继续沿用单 Workspace、单权限 epoch、真实 Olist、私有候选和原子提交。数据层提供统计口径，编译器解析真实集合并保留未修改字段，provider 负责原生会话，前端回报渲染与播放。没有理由为了这次论文增加多 worker、重试代理或通用工作流平台。

本轮发现的错误发生在这些职责的接缝：旧原生调用如何结束，工具元数据是否表达真实对象，以及图已渲染后实际截图何时能用于下一次响应。修复应落实到这些具体接缝，不能用更多全局提示词替代。

当前 15 个工具 schema 合计 15,992 JSON 字符；31 条历史输入中 25 条重复附带相同 visible/current dashboard。候选对象还重复包含嵌套 evidence。可以在保持所有候选和相同两组能力下压缩重复表示，但字符数不是 token 或账单，本轮未把压缩设成新增实验因素，也未在两次调用间更改输入契约。真实调用选中了正确主要工具路径，故不能把 `top_n` 类型失败统称为“工具太多”。

## 研究对象、动机与贡献应这样固定

研究对象是**持续语音分析中的局部修订与共同理解**。用户可以引用旧证据，却要求在当前地区、日期和指标下继续计算。历史成员身份与当前计算范围不是同一个状态。

研究问题是：**在同样支持全双工的分析环境下，把证据来源、当前修改范围、保留与解除条件显式呈现并允许纠正，是否改善修订正确性和理解，代价是多少？**

全双工提供在讲解和执行尚未结束时介入的场景。两组都全双工，所以本实验不证明全双工优于文本或轮流语音。当前共享编译器意味着支持包不是模型推理能力增强；用户看到卡片后的理解和后续纠正才是其直接可能影响的过程。

DataTone 已有可交互歧义纠正，CLEO 已有并发协作，VoCa 已有语音画布协调。增量必须是跨版本对象来源与当前分析范围的具体区分、可核验的数据后果，以及强基线下的协作证据。文献逐项核对、两条件统计和最致命的主张问题见 [RESEARCH_CLAIM_REVIEW.md](RESEARCH_CLAIM_REVIEW.md)。

CSCWD 主题上可以容纳这项协作方法研究；是否值得录用仍取决于实证发现。不能用新界面、若干成功 API 调用或大量测试替代减少误解、改善理解或刻画权衡的证据。[官方征稿](https://cscwd2027.dailyeliteevents.com.au/program.html)
