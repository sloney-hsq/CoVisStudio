# A32 — 图表呈现与渲染回执

只读检查：`frontend/src/components/ChartCard.vue`、`frontend/src/chart.js`、`frontend/src/App.vue`，以及必要的 `toolFeedback.js`、`chartVisibility.js`、`backend/data.py` 和 `backend/app.py` 调用点。

1. **P1｜当前缺陷：删除最后一图后缺少空画布回执。** 正常语音请求删除全部图表时，`App.vue:131–143` 仅替换状态；自动发送新 context 依赖 `233–242` 的图表 rendered，而空画布分支 `552–561` 已卸载所有图卡。`164` 又要求非空 views 才标 Displayed。因此新空画布不能主动确认，后端 `app.py:368–376` 的精确 revision capture 等待可能停住后续响应，直到其他交互发送 context。最小修复：空状态 DOM 更新后发送该版本的显式空 context，并完成空画布展示回执；不伪造 chart_rendered。现有 `test_committed_capture_review.py:141` 手动注入空 context，不能覆盖此前端缺口。

2. **P2｜新设计必须补：类别颜色不是身份颜色。** `chart.js:27–34,50,70` 用图级颜色和局部调色板；柱图同色，饼图按当前顺序分色。离线调用真实 ECharts SVG SSR：A/B 原顺序为 `#238579/#95c4bc`，按值降序后 B/A 得到相同色序，A 换色。跨指标比较、重排名及历史对照无法凭颜色追踪同一类别。最小建议：类别图按原始 label 共用稳定映射，图级强调色与类别身份分开；热力图继续用数值色阶。

3. **P3｜当前呈现缺口：全空指标只有空图，没有缺失说明。** 正常选 Shipped + Average delivery time 时，delivery_days 只为 delivered 计算，平均值为 null（`data.py:69–70,121,143`）。`chart.js:14` 虽返回 No data，但 `34,61,70–73` 把 null 交给图元，`ChartCard.vue:64–66` 仍只显示分组数。离线用 A/B 两行 null、开启标签，bar/heatmap 的 SVG 文本均只有 Category A/B；No data 仅存在于无法直接悬浮的缺失图元 tooltip。建议零条有效值时在卡内明确显示 No valid delivery-time data，保留范围与类别；不要补零。

验证边界：仅静态阅读和内存中的 ECharts SSR，未启服务、调 API 或验证实际浏览器。非空图已使用 finished、render generation 与 revision 检查（`ChartCard.vue:18–34`、`App.vue:233–240`）；正常数值有百分比、R$、天单位。月份仍是分类轴；数值排序导致时间连接乱序由其他审查覆盖，本报告不重复计项。
