# A20：SQL oracle 的独立性边界

检查：`backend/oracle.py`、`backend/study.py`、`scripts/audit_delivery.py`；追读 `backend/data.py:48–59`、`backend/app.py:156–180`、相关测试及当前协议。仅做两次内存内离线复现，真实 Olist 只读；未调用 API、启动服务或跑全套测试。

独立性结论：oracle 独立于运行时聚合 SQL、派生表与 `query()`，但共享 `OlistData` 的 CSV 装载、DuckDB 连接和锁（`oracle.py:23–67`、`data.py:48–59`），不是独立数据解析器或数据库引擎。当前 rev/biz/exp 的最终评分先核目标 source，再以目标计算数值；中间提交才按实际 source 复算（`study.py:296–307`）。交付审计只证明实际查询自洽，不判用户目标（`audit_delivery.py:36–45`）；`JARVIS_ADAPTATION.md:97` 明示此点，并把非品类记为 `not_checked`。未发现当前主路径把数值正确等同目标正确。

1. **P2，代码缺陷：正常改用月份会中断整份评分。** `study.py:365` 将每次实际提交送入 `_state_checks`，后者在第 307 行把实际 source 交给仅支持 category 的 oracle；`oracle.py:10–11` 直接抛错。触发：业务任务把目标图改成 month（运行时允许），随后 Finish；即使以后改回品类，重放该中间提交仍会失败。评分异常阻断 `app.py:177–180` 的报告保存。最小修复：在评分边界将非品类数值核验明确记为未覆盖，仍保留 source 不满足目标的失败项，不让单次未覆盖提交终止报告。

   离线证据：`setup_operations('biz_01_sp_priorities_mg')` 后，实际 `edit_charts` 将 v2 的 dimension 改为 month 并提交；带 request/commit 事件调用 `evaluate`，结果为 `edit_committed=true`、`ValueError: Revision-study oracle covers category charts only.`

2. **P3，历史评分限制：旧任务仍同源自检。** `study.py:84` 使用被测 `data.query(target)` 作为答案；`study.py:435` 仍可路由到此入口，旧 ID 也仍可调用（`docs/CONTRACT.md:130`）。同一聚合错误会同时污染执行与答案。离线注入只将 query 返回的 value 乘 2，按 `region_linked` 的目标执行后，旧评分 `completed=true`，独立 oracle 三图均为 false。最小修复：旧品类任务改用现有 oracle，或给旧报告明确标注“运行时复算，非独立核验”；不要把旧结果汇入独立 SQL 通过数。当前 biz/exp 不受此复用问题影响。

研究边界：动态用户意图评分仍待人工标注和 episode 规则；当前协议已明确静态任务答案不能代替参与者意图（`docs/UNIFIED_RESEARCH_PROTOCOL.md:36,68,106`），本项不把已声明的研究待办列为代码缺陷。
