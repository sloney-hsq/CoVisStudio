**未发现漏分配、重复 trial ID 或错误条件绑定。** 用 `.venv/Scripts/python.exe -B` 离线调用 `allocation_table(30)`，与保存的 JSON、CSV 逐项相等；manifest 的八份任务与 `experiment_tasks()` 相等，`assignment_sha256` 与分配 JSON 原始字节哈希一致（manifest:4、187）。120 个 trial ID 全部唯一；每槽四家族各一次、两条件各两任务、A/B 各两任务。八个材料 ID 均能解析；未见私有正确答案字段混入分配记录。

**P3｜研究分析约束，不是代码缺陷。** 普通触发是按现有30槽完成收集后直接比较条件均值。条件与位置、家族仍有上述小幅关联，学习或疲劳及家族难度可混入未经调整的差值。分配实现见 `backend/experiment.py:21–38、44–58`；部分区组已在 `docs/EXPERIMENT_PROTOCOL.md:17–21` 如实披露，测试也明确断言非完全平衡（`tests/test_experiment.py:52–58`）。最小建议是落实 `UNIFIED_RESEARCH_PROTOCOL.md:82–88`：以参与者为独立单位，控制家族、版本、位置/条件块顺序，保留失败与缺失；不必为凑整擅增人数或删槽。材料结构匹配不证明人类难度相等。
